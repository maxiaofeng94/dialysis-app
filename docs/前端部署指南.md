# 前端部署上线指南（PWA）

把 `dist/` 发布到公网，家人手机浏览器打开就能用。推荐 **Cloudflare Pages**（免费、不限流量、国内可达性相对最好）。

> 前提：`.env.production` 已填好**生产库**的 Project URL 与 anon key（本文件不入库）。
> 构建命令一律是 `npm run build`，产物目录一律是 `dist`。

---

## 路线 A：Cloudflare Pages（推荐）

### 方式 A1：直接上传（5 分钟，最简单）

1. 本地构建：
   ```bash
   npm run build
   ```
2. 打开 https://dash.cloudflare.com → 左侧 **Workers & Pages** → **Create application** → **Pages** 标签 → **Upload assets**
3. Project name 填 `dialysis`（会变成 `dialysis.pages.dev`，可自定义）
4. 把 **`dist` 文件夹整个拖进去**（或先压成 zip 再上传）
5. **Deploy site** → 等十几秒 → 拿到网址

> 每次改代码后，重新 `npm run build` 再拖一次即可（Direct Upload 不跑构建）。

### 方式 A2：连接 GitHub 自动部署（一劳永逸）

1. 先把代码推到 GitHub（仓库已存在：`maxiaofeng94/dialysis-app`）：
   ```bash
   git push origin main
   ```
2. Cloudflare → **Workers & Pages** → **Create application** → **Pages** → **Connect to Git**
3. 授权 GitHub → 选择 `dialysis-app` 仓库
4. 构建设置：
   | 项 | 值 |
   |---|---|
   | Framework preset | `Vue`（或 None） |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Root directory | （留空） |
5. **Environment variables（关键，不配就变成单机版）**：
   ```
   VITE_SUPABASE_URL        = 生产库的 Project URL
   VITE_SUPABASE_ANON_KEY   = 生产库的 anon public key
   NODE_VERSION             = 22
   ```
   > 前两个值直接从本地 `.env.production` 里抄（`npm run build` 用的就是这一套）。
   > `NODE_VERSION` 必须 ≥ 20.19，否则 Vite 8 构建会失败。
6. **Save and Deploy** → 之后每次 `git push` 自动重新构建

### 绑定自定义域名（可选，国内访问更稳）

Pages 项目 → **Custom domains** → 添加你的域名 → 按提示在 Cloudflare DNS 加一条 CNAME。
（域名需自行购买；用 `*.pages.dev` 默认域名在部分地区可能慢或被污染。）

## 路线 B：Vercel

> ⚠️ 提醒：`*.vercel.app` 默认域名在国内**经常无法访问**（DNS 污染），除非绑自定义域名，否则家人手机可能打不开。国内使用优先选 Cloudflare Pages。

1. 推代码到 GitHub（同 A2 第 1 步）
2. https://vercel.com → **Add New → Project** → Import 你的 `dialysis-app` 仓库
3. 配置：
   | 项 | 值 |
   |---|---|
   | Framework Preset | `Vite` |
   | Build Command | `npm run build` |
   | Output Directory | `dist` |
   | Install Command | `npm install` |
4. **Environment Variables** 加同样三条：`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` / `NODE_VERSION=22`
5. **Deploy** → 拿到 `xxx.vercel.app`
6. 国内可用性差的话：Settings → Domains 绑自定义域名

命令行方式（可选）：
```bash
npm i -g vercel
vercel            # 首次会引导登录与关联项目
vercel --prod     # 发布到生产
```

## 路线 C：Cloudflare Workers（Dashboard 里找不到 Pages 入口时）

Cloudflare 现在默认把新项目往 Workers 引导，Pages 入口藏得较深。仓库根目录已备好 `wrangler.jsonc`（声明静态资源目录为 `./dist`），可直接走 Workers 部署：

1. Dash → **Workers & Pages** → **Create application** → **Connect to Git** → 选 `dialysis-app`
2. 表单填写：

   | 项 | 值 |
   |---|---|
   | Project name | `dialysis`（**必须与 `wrangler.jsonc` 里的 `name` 一致**） |
   | Build command | `npm run build` |
   | Deploy command | `npx wrangler deploy`（默认值，不用改） |
   | Preview command | 保持默认 |

3. **环境变量**：创建流程里若没有该字段，先点 **Deploy** 建出项目，再进 **项目 → Settings → Build（Build variables and secrets）** 添加这三条：
   ```
   VITE_SUPABASE_URL      = 生产库的 Project URL
   VITE_SUPABASE_ANON_KEY = 生产库的 anon public key
   NODE_VERSION           = 22
   ```
   加完后到 **Deployments** 点 **Retry deployment** 重新构建 —— 构建期变量**必须重新构建**才会注入（不重新构建，站点会是单机版）
4. 网址形如 `https://dialysis.<你的账号>.workers.dev`

> 若之后 Cloudflare 又放出 Pages 入口，两种方式可以并存，互不影响；`wrangler.jsonc` 对 Pages 部署无副作用。

## 部署后必做验证

1. 手机浏览器打开网址 → 出现登录页（说明云端已生效；若直接进本地模式说明环境变量没配上）
2. 用生产库账号登录（如 `13533804875`）→ 应看到「吴二妹」与全部历史记录
3. **添加到主屏幕**：iOS Safari → 分享 → 添加到主屏幕；Android/华为浏览器 → 菜单 → 添加到桌面
4. 打开后应全屏无浏览器地址栏，图标出现在桌面

## 常见问题

| 现象 | 原因/处理 |
|---|---|
| 打开网址直接进本地单机模式（不显示登录页） | 构建时没注入环境变量：Direct Upload 要在**本地**构建好再传；Git 集成要在平台配好环境变量并重新部署 |
| 构建失败提示 Node 版本 | 平台加 `NODE_VERSION=22` |
| 页面 404（刷新子路由） | 本项目用 hash 路由（`/#/settings`），一般不会 404；若出现，给平台加 SPA fallback 到 `index.html` |
| 手机上数据不更新 | PWA 有 Service Worker 缓存：下拉刷新 / 关掉重开；必要时清站点数据 |
| 换绑新的 Supabase 项目后网页还是旧数据 | Service Worker 缓存了旧资源：重新部署并强刷（或改项目名重新部署） |
| 国内打开很慢 | 换 Cloudflare 自定义域名，或改用国内静态托管（腾讯云 EdgeOne Pages 等） |

## 更新流程（以后改代码）

- Direct Upload：`npm run build` → 重新拖 `dist`
- Git 集成：`git push` → 平台自动构建部署（记得本地 `.env.production` 与平台环境变量保持一致）
