# 透析病人体重与生命体征记录系统 — 需求与设计文档

- 版本：v1.0
- 状态：设计已确认，待实现
- 日期：2025

---

## 1. 需求背景

当前有透析病人，每次透析需要记录：

1. 上机前体重；
2. 透析过程中的多次血压测量（高压、低压）；
3. 下机后体重。

病人需坐轮椅，所以每次体重的**实际值 = 称重值 − 轮椅重量**，再报给医生。

---

## 2. 需求点（功能需求）

### 2.1 运行设备
- 支持 **华为手机**、**苹果手机**（通过 PWA 实现，一套代码两端可用）。

### 2.2 体重与脱水
- 记录每次透析的**上机前体重、下机后体重**；
- 基于**干体重**自动计算**脱水量**；
- 额外显示**回水量**（每次固定 300ml，计入机器超滤设置）。

### 2.3 血压与血糖
- 记录透析过程中的**血压**：一般每隔一小时测一次（**手动记录，不提醒**）；
- 记录**血糖**：整个过程中测一次（单位 mmol/L）。

### 2.4 不良反应
- 记录透析后可能出现的不良反应：呕吐、腿脚无力、头晕、低血压、抽筋、头痛、其他（自定义文字），可多选，可加备注。

### 2.5 报告
- 手机汇总报告页；
- 导出图片 / PDF 发微信；
- 跨多次透析的体重 / 血压趋势图。

### 2.6 使用范围
- 当前：管理 **1 个病人**，但可能有**多个人（家属/护工）在同一设备操作记录**（记录里含「记录人」字段）；
- 未来：扩展多人 / 多设备同步 / 医生远程查看。

## 3. 业务规则与计算公式

### 3.1 体重扣减轮椅重量
- 上机前实际体重 = 上机前称重值（含轮椅）− 轮椅重量
- 下机后实际体重 = 下机后称重值（含轮椅）− 轮椅重量

### 3.2 脱水量（分场景显示）
- 只输入「上机前体重」时 → 仅显示 **计划脱水量**；
- 输入「下机后体重」后 → **计划脱水量 + 实际脱水量** 都显示。

### 3.3 计算公式汇总

| 计算值 | 公式 |
|---|---|
| 上机前实际体重 | 上机前称重(含轮椅) − 轮椅重量 |
| 下机后实际体重 | 下机后称重(含轮椅) − 轮椅重量 |
| 计划脱水量 | 上机前实际体重 − 当日有效干体重 |
| 实际脱水量 | 上机前实际体重 − 下机后实际体重（仅下机后已填） |
| 回水量 | 固定 300ml（可配置） |
| 机器超滤设置 | 计划脱水量 + 回水量 ÷ 1000 |
| 年龄 | 按生日与当天计算（仅展示） |

> 单位：体重 kg；脱水量/回水量 L 与 ml 同时展示（1kg ≈ 1L）。

### 3.4 干体重取用规则
- 某次透析（日期 D）的**有效干体重** = 干体重历史表中 `生效日期 ≤ D` 的最新一条；
- 当前干体重 = 最新生效的一条；
- 从未设置干体重时，提示先到「设置」添加。

## 4. 页面原型设计

### 4.1 全局导航结构

```
底部导航（3 个页签，一级页面）
  ├─ ① 记录（透析记录列表，默认首页）
  ├─ ② 趋势（历史趋势图）
  └─ ③ 设置（病人档案 + 干体重历史 + 数据备份）

二级页面（从一级页进入，返回上级）
  ├─ 透析详情/编辑页 ← 从"记录"进入
  ├─ 报告页 ← 从"透析详情"进入
  └─ 血压/血糖录入 ← 从"透析详情"弹窗进入
```

### 4.2 页面① 记录首页（含「快速创建」）

```

├────────────────────────────────┤

│ │ 上机前体重(含轮椅)          │ │
│ │ [  72.5 ] kg   [立即创建]   │ │
│ │ ────────────────────────── │ │
│ │ 实际体重 60.5kg  计划脱水 2.5L│ │ ← 输入后实时预览
│ └────────────────────────────┘ │
│ 2025年6月                       │
│ ┌────────────────────────────┐ │
│ │ 6-20 周五  已完成  计划脱水2.5L│ │

├────────────────────────────────┤
│  [①记录]     [②趋势]    [③设置] │
└────────────────────────────────┘
```

**快速创建流程**：
1. 打开 App → 默认「记录」页，顶部即快速创建卡片；
2. 输入「上机前体重(含轮椅)」→ 实时预览实际体重与计划脱水量；
3. 点「立即创建」→ 创建一条记录（当天日期，状态=进行中）并自动跳转到该记录编辑页；
4. 在编辑页继续填写下机后体重、血压、血糖、不良反应、标记完成等；
5. 「＋新建」用于创建空白记录（可指定日期）。

## 5. 数据库设计

### 5.1 存储引擎
- **阶段一（本次）**：IndexedDB（Dexie 封装），数据存手机本地，离线可用、免费。
- **阶段二（未来多人）**：Supabase(Postgres)，表结构几乎不变，加用户表与行级权限。

### 5.2 表结构

#### 表1 `patients` 病人档案

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| name | string | 姓名 |
| birthday | string | 生日 YYYY-MM-DD（计算年龄用） |
| wheelchairWeight | number | 轮椅重量(kg) |
| rinseBackVolume | number | 回水量(ml)，默认 300 |
| createdAt / updatedAt | number | 时间戳 |

#### 表2 `dryWeights` 干体重历史

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| patientId | string | 外键 → patients |
| value | number | 干体重(kg) |
| effectiveDate | string | 生效日期 YYYY-MM-DD |
| note | string \| null | 备注（如"医生调整"） |
| createdAt / updatedAt | number | 时间戳 |

#### 表3 `sessions` 透析记录

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| patientId | string | 外键 → patients |
| date | string | 透析日期 YYYY-MM-DD |
| preWeightMeasured | number \| null | 上机前称重(含轮椅)kg |
| postWeightMeasured | number \| null | 下机后称重(含轮椅)kg |
| wheelchairWeightUsed | number | 轮椅重量快照(kg) |
| rinseBackVolumeUsed | number | 回水量快照(ml) |
| operator | string \| null | 记录人（阶段一） |
| status | 'ongoing' \| 'completed' | 进行中/已完成 |
| notes | string \| null | 备注 |
| createdAt / updatedAt | number | 时间戳 |

#### 表4 `bloodPressures` 血压

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| sessionId | string | 外键 → sessions |
| measuredAt | number | 测量时间戳 |
| systolic | number | 高压 mmHg |
| diastolic | number | 低压 mmHg |
| note | string \| null | 备注 |

#### 表5 `bloodGlucoses` 血糖

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| sessionId | string | 外键 → sessions |
| measuredAt | number | 测量时间戳 |
| value | number | 血糖值 mmol/L |
| note | string \| null | 备注 |

#### 表6 `adverseReactions` 不良反应

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| sessionId | string | 外键 → sessions |
| type | string | 类型 key |
| detail | string \| null | 自定义文字/备注 |
| severity | 'mild'\|'moderate'\|'severe' \| null | 严重程度（可选） |
| recordedAt | number | 记录时间戳 |

#### 表7 `users` 用户/账号（阶段二实现）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键（关联登录账号） |
| name | string | 显示名 |
| phone | string \| null | 手机号（登录标识，可空） |
| avatar | string \| null | 头像（可选） |
| createdAt / updatedAt | number | 时间戳 |

#### 表8 `patientMembers` 病人-成员关系（阶段二实现）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| patientId | string | 外键 → patients |
| userId | string | 外键 → users |
| role | 'owner' \| 'caregiver' \| 'doctor' \| 'viewer' | 该成员对该病人的权限 |
| createdAt | number | 加入时间 |

### 5.3 计算字段规则（不落库，运行时计算）

| 计算值 | 公式 |
|---|---|
| 上机前实际体重 | preWeightMeasured − wheelchairWeightUsed |
| 下机后实际体重 | postWeightMeasured − wheelchairWeightUsed |
| 计划脱水量 | 上机前实际体重 − 当日有效干体重 |
| 实际脱水量 | 上机前实际体重 − 下机后实际体重 |
| 回水量 | rinseBackVolumeUsed |
| 机器超滤设置 | 计划脱水量 + 回水量 ÷ 1000 |

### 5.4 关系与索引

```
patients 1 ── N dryWeights
patients 1 ── N sessions 1 ── N bloodPressures
                          ├── N bloodGlucoses
                          └── N adverseReactions

（阶段二）users ── N patientMembers ── patients
```

- 索引：`dryWeights(patientId+effectiveDate)`；`sessions(patientId+date)`、`sessions(patientId+createdAt)`；血压/血糖/不良反应按 `sessionId`。
- 删除 session 时级联删除其血压/血糖/不良反应。

### 5.5 不良反应类型字典

| key | 显示 |
|---|---|
| vomit | 呕吐 |
| legWeakness | 腿脚无力 |
| dizziness | 头晕 |
| hypotension | 低血压 |
| cramp | 抽筋 |
| headache | 头痛 |
| other | 其他（自定义文字） |

### 5.6 字段变更（阶段一 → 阶段二）

| 阶段 | 字段 | 说明 |
|---|---|---|
| 阶段一（本地单人） | `sessions.operator`(string) | 手动填写的"记录人"姓名 |
| 阶段二（多人） | `sessions.operatorId`(string, FK→users) | 自动记录操作者，原 operator 字段废弃 |

### 5.7 权限矩阵（阶段二，RLS 行级权限）

| 角色 | 查看数据 | 新增/编辑记录 | 改干体重 | 管理成员 |
|---|---|---|---|---|
| owner（本人/主管理员） | ✓ | ✓ | ✓ | ✓ |
| caregiver（家属/护工） | ✓ | ✓ | ✗ | ✗ |
| doctor（医生） | ✓ | 只读 | ✗ | ✗ |
| viewer（只读） | ✓ | ✗ | ✗ | ✗ |

## 6. 技术架构设计

### 6.1 总体架构：PWA（渐进式 Web 应用）

```
[华为手机 / 苹果手机 浏览器]  ←→  [PWA 前端 (静态资源, 免费托管)]
                                        │
                                        ├─ 本地数据库 IndexedDB（阶段一）
                                        └─ 云端后端 Supabase（阶段二，多端同步）
```

**为什么选 PWA**：华为（HarmonyOS/Android）与苹果（iOS）一套代码都能用；浏览器"添加到主屏幕"即可像 App 一样运行、离线可用；免上架应用商店，部署零成本。

### 6.2 技术选型

| 层 | 技术 |
|---|---|
| 前端框架 | Vue 3 + Vite + TypeScript |
| 移动端 UI | Vant 4 |
| 本地存储 | Dexie.js（IndexedDB） |
| PWA | vite-plugin-pwa |
| 图表 | ECharts |
| 报告导出 | 图片/PDF 导出 |
| 路由 | Vue Router |

### 6.3 数据访问分层（先单人、后多人）

```
前端页面/业务逻辑  ──►  Repository 接口
                            ├─ LocalRepository（Dexie/IndexedDB）   ← 阶段一
                            └─ CloudRepository（Supabase）          ← 阶段二
```

- 阶段一：`LocalRepository`，零后端、离线可用、完全免费；
- 同设备多操作人：加「记录人」字段即可；
- 阶段二：新增 `CloudRepository` + 登录，前端页面与计算公式不变。

| 方案 | 成本 | 国内访问 | 说明 |

## 9. 附录：已确认决策清单

1. 设备：华为 + 苹果（PWA）。
2. 脱水量分场景显示：仅上机前→只显示计划；输入下机后→计划+实际都显示。
3. 回水量：固定 300ml，计入机器超滤设置（= 计划脱水量 + 0.3L）。
4. 血压：高压+低压（无心率），手动记录，不提醒。
5. 血糖：mmol/L，每次透析 1 次。
6. 不良反应：呕吐、腿脚无力、头晕、低血压、抽筋、头痛、其他（自定义），可多选。
7. 报告：汇总页 + 导出图片/PDF + 跨次趋势图。
8. 使用范围：单人自用、多操作人；未来多人扩展。

## 10. 多人版技术方案（定稿）

### 10.1 总体架构

```
[前端 PWA/APK (Vue3)]  ──►  Repository 接口
                                ├─ CloudRepository（Supabase）   ← 多人版
                                └─ LocalRepository（IndexedDB）   ← 保留（离线/单机兜底）
                                         │
                      Supabase（Postgres + Auth + RLS + Edge Functions）
                                         │
                              （无短信服务商，登录采用手机号+密码）
```

### 10.2 认证方案：手机号 + 密码 + 持久登录

**注册/登录流程**
1. 注册：填手机号 + 密码（≥6 位）→ 调 Edge Function `register`（服务端密钥建号，Supabase Auth 用伪邮箱 `{手机号}@phone.local`，`users` 表存真实手机号）；
2. 登录：手机号 + 密码 → `signInWithPassword` 直接登录；
3. 前端拿到会话 token 持久保存。

**持久登录（减少登录频次）**
- 网页/PWA：localStorage 存 refresh token，重开自动恢复；
- APK：`@capacitor/preferences` 存 token，杀进程重开自动恢复；
- access token 过期 → 静默刷新（refresh token 换新）；
- 仅当 refresh token 失效（换手机/清除数据/极长期未用）才需重新登录。

**成本**
- 无需短信服务商，0 成本、无资质要求（密码存储由 Supabase Auth 托管）。

### 10.3 数据库新增（Postgres）

| 表 | 说明 |
|---|---|
| `users` | id(uuid PK, 关联 auth.users)、name、phone、created_at |
| `patient_members` | patientId + userId + role(owner/caregiver/doctor/viewer)，unique(patientId,userId) |
| `sessions.operatorId` | 原 `operator`(文本) 改为 `operatorId`(uuid FK→auth.users)，自动记录操作人 |
